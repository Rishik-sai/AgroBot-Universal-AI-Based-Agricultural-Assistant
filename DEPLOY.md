# Deploying AgroBot to Render

The deployable app is **`batch -13 AgroBot Universal AI-Based Agricultural Assistant/`**.
`render.yaml` (repo root) points Render at it, so you don't configure anything by hand.

## 1. Get your API keys

| Key | Where to get it |
|---|---|
| `GEMINI_API_KEY` | https://aistudio.google.com/apikey |
| `WEATHER_API_KEY` | https://openweathermap.org/api (free tier) |

`FLASK_SECRET_KEY`, `ADMIN_PASSWORD` and `DEMO_PASSWORD` are generated by
Render automatically.

The repo previously carried a hardcoded OpenWeatherMap key. It is now read
from the environment, but it is still in the git history, so **rotate it** at
https://home.openweathermap.org/api_keys.

## 2. Push to GitHub

```bash
git add -A
git commit -m "Add Render deploy config"
git push origin main
```

## 3. Create the Blueprint

1. Go to https://dashboard.render.com → **New** → **Blueprint**
2. Connect the repo `Rishik-sai/AgroBot-Universal-AI-Based-Agricultural-Assistant`
3. Render reads `render.yaml` and shows one web service (`agrobot`) plus one
   Postgres database (`agrobot-db`)
4. It prompts for `GEMINI_API_KEY` and `WEATHER_API_KEY` — paste them in
5. **Apply**

First build takes ~5 minutes. Your URL will be `https://agrobot.onrender.com`.

## 4. Log in

The app seeds two accounts on first boot:

- Admin:  `admin@aiagrobot.com`
- Farmer: `demo@aiagrobot.com`

Their passwords come from `ADMIN_PASSWORD` / `DEMO_PASSWORD`. On Render those
are generated by the Blueprint — read them from the service's
**Environment** tab. Locally they are in your `.env`.

If neither var is set, the app mints a random password and prints it once to
the startup log. No password is hardcoded in the source any more.

## Health checks

- `/check-db` — database connectivity and table list
- `/test-gemini` — whether the Gemini key works
- `/test-key` — whether the weather key is set

## Things to know about the free tier

- **The service sleeps** after 15 minutes idle; the next request takes ~50s to
  wake it. Fine for a demo, not for a live audience.
- **Uploaded files do not survive a redeploy.** Render's free disk is
  ephemeral, and crop/pest photos are written to `static/uploads/`. For
  persistence you need a Render Disk (paid) or object storage such as S3 or
  Cloudinary.
- **Free Postgres expires after 30 days.** Render emails you first.
- **One worker only.** `-w 1` is deliberate: Flask-SocketIO needs a shared
  message queue (Redis) before it can run multiple workers. Scaling up without
  one silently breaks chat.

## Running it locally

```bash
cd "batch -13 AgroBot Universal AI-Based Agricultural Assistant"
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # then fill in your keys
python app.py             # http://localhost:5000
```

To run locally exactly as Render does (gunicorn, no debug reloader):

```bash
gunicorn -k geventwebsocket.gunicorn.workers.GeventWebSocketWorker \
  -w 1 -b 0.0.0.0:5000 wsgi:app
```

With no `DATABASE_URL` set, the app falls back to SQLite at `data/agrobot.db`.
